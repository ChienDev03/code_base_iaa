# Room and local data

## Ownership

Room/SQLite stores categories, budgets and transactions in private `money_tracker.db`.
DataStore (`AppSettings`) owns small preferences (`darkTheme`, `currency`, `onboardingCompleted`),
so the research schema's app_settings table is not duplicated.
The source reference is D:/moneytracker/database/schema.sql; it is not automatically executed/imported.
Room's exported schema is authoritative for this application.

MoneyDatabase is version 1, uses WAL, foreign keys, KSP and schema export.
DatabaseModule provides one singleton. LedgerRepository is bound in RepositoryModule.
The example repository remains an in-memory UI demonstration and never seeds the financial database.

## Contracts

- Store money as Long minor units, never Float/Double. Currency is a three-letter uppercase code.
- Timestamps are Unix seconds, not milliseconds; callers supply creation/occurrence time.
  The repository stamps update time using injected TimeProvider.
- Repository writes reject blank names/IDs and negative amounts. It rejects cross-currency budget
  associations and currency changes while incompatible transactions are attached.
- SQL foreign keys use SET NULL: deleting a category/budget retains its transactions.
- Parent inserts and updates reject duplicate names and missing update targets. Transaction upserts
  update rows instead of REPLACE deleting/reinserting parents.
- BudgetSummary calculates expenses and remaining amounts; income/loan rows do not count as spending.
- DAO snapshot reads share one transaction. No network, account, sync, upload or financial telemetry.
- No main-thread query allowance and no destructive migration fallback.
- Expose DAO operations through repositories so validation and safe failure mapping are retained.
  The reference SQL CHECK constraints are enforced by repository validation in this Room schema;
  do not bypass that boundary with raw writes.
- Full snapshots suit the starter. Add filtered/paged queries when a real screen requires them.
- Android backup/device transfer retain the existing disabled policy; backup/export UI is not added.

## Migration

Commit app/schemas/com.your.sourbase.core.database.MoneyDatabase/1.json generated by KSP.
For version 2+, increment the version, supply a data-preserving Migration (or reviewed AutoMigration),
register it on the builder and verify upgrades against the exported previous schema.
There is no pre-existing Room version to migrate and no import from the research app's storage.
